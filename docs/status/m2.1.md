# m2.1 — Engine: deliveries workflow, approve/reject, relay header, echo filter

## Task
M2.1 per the packet: forward/approve/reject flow, delivery_update, snapshot deliveries,
the SPEC relay header, ack-timeout and disconnect failure, start-reset to pending,
insertMessage echo filter. Carried minors B1 (listen error), B2 (token change → close 1000),
B4 (ulid max(now, last)). No protocol changes beyond the listed SPEC rows.

## Result
- forward: codex-only target; unknown message, non-codex target and self-source are ignored
  (logged); inserts pending_approval or resets a failed row; idempotent otherwise; broadcasts
  delivery_update on every change.
- approve: pending_approval → queued; if the target adapter is connected, sends one deliver
  (`[Relay · from Astra · #<id> · hop 1]
<body>`), marks delivering (attempts+1) and arms an ack
  timer (deliverAckTimeoutMs, default 30 s, injectable). Approve twice → still one deliver.
  No adapter → stays queued; the adapter's hello sends queued rows oldest-first, once.
- reject: pending/queued → cancelled (final). delivered/failed accepted only from the socket
  registered as the delivery's target, only while delivering. Ack expiry → failed
  "no confirmation from adapter"; target disconnect mid-delivery → failed
  "adapter disconnected before confirming". Nullable deliveries.error column, added via
  ALTER TABLE for pre-existing relay.db files.
- Engine start: resetInFlightToPending() puts queued/delivering rows back to pending_approval
  (store function, tested) — no replay, ever.
- Echo filter in insertMessage: StoreError('echo') when the hash matches a message delivered
  to the same source within 10 minutes; the engine drops it like a duplicate (no broadcast).
- Snapshot now carries deliveries (non-user rows of the snapshot's messages).
- B1: EADDRINUSE prints "cannot listen on 127.0.0.1:8787 (port in use)"; other errors print
  code + message. B2: token change closes the extension socket with 1000 and reconnects at
  once (1000 never sets authRejected, never counts as replaced); marker bumped to
  2026-10-19.4, dist rebuilt. B4: ulid clamps to max(now, last).

## Surprises
- A socket's close event can fire after engine stop() closed the store — the new close
  handler's store query threw "database is not open". Fixed with a stopped flag: shutdown is
  not an adapter disconnect, so in-flight rows survive a stop for the next start's reset
  (which is also the correct no-replay semantics).
