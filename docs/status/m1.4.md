# M1.4 — chatgpt-ext adapter (astra)

Task: M1.4, `adapters/chatgpt-ext/`: turn the M0.2 extension spike into the adapter that reports completed chatgpt.com replies to the engine. The spike stays in `spikes/chatgpt-extension/` as the frozen M0.2 artifact; the adapter is new code under `adapters/chatgpt-ext/` (the SPEC's repo layout), carrying over the spike's live-proven detection logic.

Result: pass — all automated checks green (`tsc --noEmit` clean; `npm run build:ext` rebuilds the committed `dist/`; 48 tests, 0 failures). The live smoke on a logged-in chatgpt.com tab is the publisher's step; instructions below.

## What was built

- `src/content.ts` — the spike's detection logic (witnessed streaming + stop button gone + turn `complete` + 1.5 s stable text, keyed by `data-dil-message-id`), now reporting through the service worker instead of console.logging.
- `src/background.ts` — MV3 service worker; owns the one engine socket: `{type:'auth', token}` first frame, then `{type:'hello', name:'astra', version}`. Forwards `captured` (body = the reply text, sourceRef = the page's `data-dil-message-id`) and `status`. Re-reads the token from `chrome.storage.local` on every attempt; 2 s reconnect; a 30 s watchdog alarm (MV3 kills idle workers); queues captures while the socket is down; stops retrying on auth rejection (4401) until a new token is pasted.
- `options.html` + `src/options.ts` — publisher's decision: token pasted once (validated as 64-hex), lives in `chrome.storage.local`. Saving triggers an immediate connect via `storage.onChanged`.
- `popup.html` + `src/popup.ts` — the PONG test typer carried over unchanged (never presses Send).
- `src/protocol.ts` — the pure logic (header-echo guard, status precedence, header-bar stripping), testable in Node.
- `src/selectors.ts` — every selector and both page attribute names (`data-talvt-turn-state`, `data-dil-message-id`) in one file.

## How to test (publisher)

1. `npm run build:ext` (already run; `dist/` is committed and in sync with `src/`)
2. Start the engine (`node relay/engine.ts`)
3. `chrome://extensions` → Developer mode → **Load unpacked** → select `adapters/chatgpt-ext/` (disable the old M0.2 spike so there are not two content scripts)
4. Open the extension's **Options** page; paste the token from `%APPDATA%\RelayChat\token`; Save. The service worker console (chrome://extensions → "service worker" link) should show `engine connection open`
5. Open chatgpt.com, send a message; when the reply completes, the page console shows `[relay-astra] reply reported to the engine (message-id …)` about 1.5 s after completion (the stability window)
6. Ask for a reply containing a code block; check the capture has no stray "Python"/"Run" lines. If labels survive, paste the reply element's `outerHTML` from the page console (see Open questions 1)
7. Reload the tab, switch conversations: nothing re-reports (witness logic, unchanged from M0.2)
8. Popup → type the PONG prompt, you click Send — the reply reports like any other
9. Stop the engine, send a chatgpt reply → the capture queues; restart the engine → it arrives (worker console: `captured frame sent`)
10. If the page breaks a selector again: a conversation URL with zero turns logs the delayed `WARNING: no turns found …` once and the engine's astra status becomes `selectors_stale`

## Surprises

- The first-ever strict typecheck of the repo surfaced: (a) exactly the bug class carry 4 exists to catch — script-scope name collisions across popup/options (`status` even collides with lib.dom's global `window.status`); fixed by making them modules; (b) TS narrowing does not cross function walls, so the worker's chrome-API guard needed a narrowed const; (c) three latent nullable-stdio type errors in the reviewed codex adapter — fixed at the type level only.
- `spikes/codex-resume.ts` (M0.1) has stale relative imports — it references `../codex-schema/…` from its original repo-root location and cannot run from `spikes/` as-is. Frozen artifact, not touched; excluded from typecheck.
- MV3 lifecycle: Chrome kills an idle service worker (~30 s without activity), which closes the socket — the engine broadcasts `disconnected`, then `idle` again when the watchdog alarm revives the worker and it re-hellos. The astra status may flap during long idle periods.
