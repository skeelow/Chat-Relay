# m1.4-fixes — astra adapter review fixes (F1–F4) + two SPEC rows

## Task
Apply the M1.4 review fixes per the packet: F1 lost line breaks, F2 status lost on
worker restart, F3 queued captures lost on token rejection, F4 worker keepalive ping,
plus the two SPEC protocol rows (coordinator decisions D2 + ping).

## Result
- F1: `replyText(reply, mount)` mounts the stripped clone via an injected
  `mount(el) → unmount` (offscreen `position:fixed; left:-100000px`, supplied by
  content.ts), reads `innerText` while attached, unmounts in a `finally`.
  protocol.ts stays DOM-free; the test stub now models real browsers (a detached
  element's `innerText` is flat textContent).
- F2: the worker remembers the latest status in `chrome.storage.session` and replays
  it after every successful `hello` unless it is `idle` (pure
  `statusToReplayAfterHello` in protocol.ts). Status replies now carry a truthful
  `sent: true/false`.
- F3: captures drain only ≥500 ms after `onopen` and only while the socket is still
  open; a 4401 close keeps the undrained queue; the queue is mirrored to
  `chrome.storage.session` (capped at 20, newest wins) and restored on worker revival
  before the first connect. Engine and protocol untouched (ack is M2.1 work).
- F4: `{"type":"ping"}` every 20 s while the socket is open (per-connection timer,
  cleared in `onclose`; a replaced socket's close cannot clear the live one's).
  `minimum_chrome_version: "116"` added to manifest.json.
- SPEC: `status` payload now lists `selectors_stale (astra only)`; new `ping` row
  added directly after `captured`. Nothing else in SPEC changed.

## Surprises
- The old stub added block newlines even on a detached clone — the exact opposite of
  real browsers, which is why the tests missed F1. Repinning the stub kept all five
  original strip tests green while the two new mount tests failed for the right reason.
- The stub renders a blank line between adjacent `<li>`s where Chrome gives one `\n`;
  the mounted-read test asserts `/one\n+two/` ("different lines") instead of cloning
  Chrome's exact layout.

## Open questions

- `chrome.storage.session` is cleared when the browser closes entirely, so captures
