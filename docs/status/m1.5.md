## What was built

### Store — `relay/store.ts`
- `recentMessages(limit)`: the newest `limit` messages, oldest first, ordered by id (ULIDs are time-ordered). `targets` are rebuilt from the deliveries rows, sorted. A `limit` <= 0 returns nothing (SQLite would read a negative LIMIT as unlimited).
- Worth knowing: the ULID suffix is random within one millisecond, so two captures in the same millisecond have no defined relative order. Tests use explicit ids / 10 ms gaps to stay deterministic.

### Engine — `relay/engine.ts`
- `{type:'gui_hello'}`: only authenticated non-adapter sockets may send it. A socket that already sent adapter `hello` is closed 4400; pre-auth it is closed 4401 (existing rule, now covered for gui_hello too). A duplicate gui_hello is ignored — one snapshot per connection.
- Reply once, to that socket only: `{type:'snapshot', statuses:{codex, astra}, messages: store.recentMessages(200)}`. A participant with no connected adapter reads 'disconnected'.
- The engine keeps the current status per participant (hello → idle, status frames, disconnect → disconnected), so a late-joining GUI's snapshot reflects reality.
- `broadcast()` reaches only sockets that sent gui_hello; authenticated sockets that sent neither hello nor gui_hello receive nothing.
- Nothing is ever sent to adapters because of this; the no-replay rule (nothing re-sent to the AIs) still holds — stored rows reach a GUI only inside its snapshot.

### GUI — `app/`
- Electron 44.9.0 devDependency; the binary downloads on first use (`npx electron --version` triggers it) — npm's allow-scripts policy did not block it, unlike esbuild (left blocked as before).
- `main.cjs` (bundled CJS, committed dist): opens the window, hands the renderer the token via `ipcMain.handle` (re-read per request; Chromium pages cannot read %APPDATA%), and forwards the renderer's console to stdout — that is the headless verification path.
- `preload.cjs`: the only bridge — `getToken()` through `contextBridge`; contextIsolation + sandbox on, nodeIntegration off.
- `renderer.js` (IIFE bundle): connect → auth → gui_hello → render the snapshot (messages + pills) → apply `transcript_update` / `status_update` on top → skip any message id already shown. Reconnects every 2 s and re-reads the token per attempt. All relayed text renders via `textContent`, never `innerHTML`.
- Window: transcript with sender labels (Astra/Codex/You), a status pill per AI with distinct colors (including `selectors_stale` from M1.4), an engine-connection indicator. No input box. CSP meta tag set; new `console-message` event signature used (see Surprises).

## Surprises

- Backgrounding a bare `node script.ts` on this host spawns a DETACHED node.exe: the bash wrapper prints "stdin is not a tty" and dies while the real server keeps running — my first engine start "failed" but lived on as an orphan holding port 8787 (EADDRINUSE on the next start). Background servers now go through `npm run start:engine`, whose children stay attached and killable. (Documented in the electron-gui skill.)
- Killing the GUI's npm session orphans the electron.exe tree (4 processes; the window lingers on the desktop). Cleanup is `taskkill /F /T` with single slashes; process kills route through the consent flow, so cleanup happens while the publisher is present — it did, this run.
- Electron logs exactly two launch warnings on a default app: a missing CSP (fixed with a meta tag — script-src 'self', connect-src ws://127.0.0.1:8787) and the deprecated positional `console-message` signature (fixed to the event-object form). Both are gone in the final build; the smoke output is now signal-only.
- The ULID order caveat above: id ordering is millisecond-precise. Harmless at human typing speed; worth remembering if two captures ever race inside one millisecond.
