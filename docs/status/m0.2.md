# M0.2 — ChatGPT extension spike

Task: M0.2, `spikes/chatgpt-extension/`: a Manifest V3 extension with one content script on `https://chatgpt.com/*`, logging only (it sends nothing), completion detection by two signals together, and a popup button that types the test prompt without sending.
Result: partial — the extension is built and its build verified; all four behavioral acceptance checks need the publisher's logged-in Chrome (the agent cannot load an unpacked extension into the user's browser, and the logged-out chatgpt.com shell hides the composer).

Acceptance checks:

- [ ] Each completed reply is logged exactly once, never mid-stream — implemented: completion requires BOTH signals (the stop button has returned to send AND the last assistant text is unchanged for 1.5s), a sha256 dedupe set logs each message once, and ticks while the stop button is present are ignored. Needs publisher verification in the console.
- [ ] Code blocks and paragraphs survive intact — implemented: the log uses the assistant element's `innerText` (paragraph breaks and `<pre>` content survive). Needs publisher verification with a reply containing a code block.
- [ ] Reloading the page does not re-log old messages as new — implemented: every message already on the page is hashed into the seen-set at load. Needs publisher verification.
- [ ] Typed test text appears in the box and waits for the user — implemented: the popup button types `[Relay · test] Reply with PONG.` into the composer (insertText for contenteditable, value+input event for a textarea) and never touches the send button. Needs publisher verification.

How to test (publisher):

1. `npm run build:ext` (already run; `dist/` is committed, so this is optional)
2. `chrome://extensions` → Developer mode → **Load unpacked** → select `spikes/chatgpt-extension/`
3. Open chatgpt.com with DevTools console visible; send a message — the completed reply must appear as one `[relay-spike]` log with its hash, never mid-stream
4. Click the extension's toolbar button → the PONG prompt appears in the composer and waits; you click Send
5. Reload the tab → old replies must NOT re-log

Files changed: `spikes/chatgpt-extension/` (manifest.json, popup.html, build.mjs, src/selectors.ts, src/content.ts, src/popup.ts, dist/content.js, dist/popup.js), `package.json` (+esbuild devDependency, +`build:ext` script), `docs/status/m0.2.md`. `npm test` still 13/13 after the change.

Surprises:

- The logged-out chatgpt.com shell gates the composer entirely (no `#prompt-textarea`, no send/stop buttons), so selectors could not be verified against a logged-in page by the agent. They use the long-standing stable attributes (`data-message-author-role`, `data-testid` send/stop) plus aria-label fallbacks, isolated in `selectors.ts` per the SPEC — if the page has moved on, the fix goes there and only there.
- MV3 content scripts cannot use ES modules, so the spike needs a small esbuild bundling step (`build.mjs`, run via `npm run build:ext`). `dist/` is committed so the extension loads without building.
- npm blocked esbuild's postinstall script (install-scripts security warning); the build works regardless, and behaves the same on a fresh clone. Approving the script is left as a publisher security decision.
