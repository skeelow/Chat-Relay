# m2.3 — GUI: Send to Codex, approval flow, pending count (+ adapter A1/A2)

## Task
M2.3 per the packet: the astra Send-to-Codex button, D9 status lines, the header
pending count, GUI safety, and adapter minors A1/A2. No protocol/SPEC changes.

## Result
- app/src/deliveries.ts (new, pure): the D9 status table; sendButton (astra only:
  no delivery → Send to Codex, failed → Send again, else hidden; other sources never);
  pendingCount; applyDeliveryUpdate (pure; keeps rows for not-yet-shown messages);
  exact-JSON frame builders for forward/approve/reject.
- renderer.ts: an astra footer (status line + buttons) driven only by snapshot
  deliveries + delivery_update; a click sends the frame then disables the item's
  buttons until its next delivery_update; all buttons disable while offline;
  textContent everywhere, error text included. index.html: #pending badge
  ("N pending", hidden at 0) + footer CSS. package.json: the new test file joined
  npm test. app/dist rebuilt and committed.
- Adapter A1: a failed resolveThread is remembered — new delivers fail at once with
  "relay thread not resolved: <error>"; the next config clears it and retries. A2: a
  CLI thread id logs "(from command line — saved; later runs reuse it)"; usage says so.
