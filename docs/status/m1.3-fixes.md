# M1.3 fixes — Codex adapter robustness

Task: M1.3 fixes from the review — `adapters/codex/adapter.ts` and `tests/codex-adapter.test.ts` only.
Result: pass

Fixes, each with its test:

1. **Request timeout — a hung app-server can no longer freeze polling.** `RequestTracker` (exported for hermetic testing) wraps every pending request with a timer (default `REQUEST_TIMEOUT_MS = 10000`): on timeout the pending entry is deleted and the request rejects with `Error('codex request timed out: <method>')`; a response arriving later for the timed-out id finds no entry and is ignored. The timer is cleared when a response settles. A hung poll therefore counts as a poll failure, so five in a row report `disconnected` exactly as designed.
   Tests: a request that never gets a response rejects after the timeout; a late response after the timeout is ignored without throwing and the tracker keeps working for new ids; a response before the timeout resolves the request and duplicate late responses are ignored. All without spawning codex.

2. **No history dump on first run.** `planPoll` takes a `firstPoll` parameter (`ObservedTurn` gained `completedAt`). On the first successful poll, a completed turn is captured only if its `completedAt` is within the last 600 seconds; older turns — and any completed turn with a null `completedAt` — go to `seenWithoutCapture` and are never replayed later. `main()` passes `firstPoll = true` only until the first poll that succeeds, then flips it; the excluded turns are marked seen in that same poll, so a send failure at startup cannot resurrect the history later.
   Tests: first poll with turns completed 30 s ago and 2 hours ago → only the 30 s one is captured, the 2 h one is in `seenWithoutCapture`; the same input with `firstPoll` false captures both; a completed turn with null `completedAt` on the first poll is treated as history.

3. **Streaming status for long turns.** Live check first, on a dedicated test thread only: while a long turn (a 600-word story) ran, an observer's `turns/list` logged the newest turn every second; then the turn was interrupted via the protocol's `turn/interrupt` (the call the UI Stop makes) and the observation continued.
   **Observed:** while live, the foreign turn reads `status=interrupted, startedAt=1792378464, completedAt=null` — all 12 seconds. After the interrupt, `completedAt` was set (1792378477) immediately and stayed set for all 8 subsequent observations.
   Because the live turn shows `completedAt === null` and the interrupted turn shows `completedAt` set, the rule changed to: **streaming if status is `inProgress`, or status is `interrupted` and `completedAt` is null** — and `STREAMING_WINDOW_SEC` is gone. A 10-minute-old long turn now stays `streaming` for its whole run, and a genuinely interrupted turn reads `idle` immediately.
   Tests: `interrupted` + `completedAt` null + started 10 minutes ago → streaming; `interrupted` + `completedAt` set → idle; `inProgress` → streaming.

4. **Token re-read on reconnect.** `connectEngine` now takes the token *path* and re-reads the file on every attempt (the value is never logged), so a token recreated by a restarted engine is picked up. A missing file logs one line (once per outage, not per retry) and keeps retrying every 2 s; the startup hard-exit on a missing token is gone.
   Verified by construction (the path-based re-read); no unit test, since the module-level socket wiring is exercised by the live smoke and the M1.5 GUI work ahead.

Protocol, engine, store, and the adapter's read-only nature are unchanged: no `turn/start`, `thread/start`, or `thread/resume` anywhere.

Suite result: **39 tests, 0 failures** (13 store + 11 engine + 15 adapter).
