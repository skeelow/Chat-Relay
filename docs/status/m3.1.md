# m3.1 — ChatGPT adapter deliver: typing only; both directions in engine/GUI

## Task
M3.1 per the packet: the extension types relayed text and never presses Send;
forward now runs both ways (Codex → ChatGPT); GUI carry-overs G1+G2.

## Result
- Extension: the worker relays deliver to the ChatGPT tab that most recently
  messaged it (sender.tab.id; no new permissions; no tab or a dead tab → failed
  at once, never retried). The content script runs the page rules in order —
  missing composer (selectors_stale + "input box was not found (page changed?)"),
  streaming ("still replying — wait, then forward again"), existing draft
  ("already has text — send or clear it, then forward again") — then types line
  by line (insertText + insertLineBreak, never Enter), verifies with a
  whitespace-collapsed match, clears and fails on mismatch. `delivered` means
  typed, waiting for the user's Send click (D10; the extension-clicks-Send
  setting is deferred to M4.2). Manifest description updated, version 0.2.0;
  both BUILD_MARKERs → 2026-10-20.1; dist rebuilt, second build no diff.
- Engine: forward accepts codex and astra (≠ source). Header, ack timer, E1/E2,
  hello flush, restart reset and the echo filter were already target-generic —
  they now cover astra. SPEC changed only in the forward row and the M3.1 line.
- GUI (G1+G2): rows keyed messageId:target; pendingClicks clear on snapshot and
  on their own update; astra labels ("waiting for the ChatGPT extension",
  "Typing into ChatGPT…", "Typed into ChatGPT — click Send there"); codex
  messages get "Send to ChatGPT", astra keeps "Send to Codex"; pending count
  covers every target.
